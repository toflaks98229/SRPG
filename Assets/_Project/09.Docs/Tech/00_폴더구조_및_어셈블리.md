# 폴더 구조 및 어셈블리 정의

> 작성일: 2026-08-07
> 기준: `E:\GamePJ\SCPPJ\Assets\_Project` 구조를 참조하여 SRPG 프로젝트에 맞게 재구성

---

## 1. 원칙

- 모든 프로젝트 산출물은 `Assets/_Project/` 아래에만 둔다. 외부 에셋(Asset Store, 서드파티)은 `Assets/` 최상위에 그대로 두어 **우리 코드와 남의 코드를 물리적으로 분리**한다.
- 최상위는 `NN.이름` 숫자 접두사로 정렬을 고정한다. Unity 프로젝트 창에서 순서가 흔들리지 않게 하기 위함이다.
- 스크립트는 **어셈블리 정의(asmdef)로 계층을 강제**한다. 폴더는 관례일 뿐이지만 asmdef는 컴파일러가 지켜준다.

## 3. 어셈블리 계층

의존은 **한 방향으로만** 흐른다. 아래 계층이 위 계층을 참조하는 일은 없다.

```
SRPG.Common          (공용 타입 · 인터페이스 · 상수. 의존 없음)
   ↑
SRPG.Data            (ScriptableObject 정의, 세이브 데이터 스키마)
   ↑
SRPG.Framework       (엔진 유틸: 풀링, 입력 래퍼, 시간, 수학, 디버그)
   ↑
SRPG.Core            (부트스트랩, DI, 이벤트 버스, 매니저, 세이브, 상태머신)
   ↑
SRPG.Systems         (AI · 패스파인딩 · 전투 · 진형 · 시야 · 스탯 — 순수 시스템)
   ↑
SRPG.Gameplay        (유닛 · 분대 · 명령 · 카메라 · 섬 · 캠페인 — 게임 객체)
   ↑
SRPG.UI              (HUD · 컨트롤러 · 위젯 · 월드스페이스 UI)
   ↑
SRPG.Composition     (전 계층을 엮는 조립 지점. 여기서만 전부를 안다)

SRPG.Editor          (Editor 전용. 전 계층 참조)
SRPG.Tests.EditMode  / SRPG.Tests.PlayMode
```

**왜 이렇게 나누는가**: `Systems`가 `Gameplay`를 모르기 때문에, AI·패스파인딩 로직을 게임 객체 없이 EditMode 테스트로 검증할 수 있다. 전투 AI가 핵심인 프로젝트에서 이 분리는 선택이 아니라 필수다.

## 5. 현재 asmdef 참조 상태 (중요)

**현재 asmdef는 SRPG 프로젝트에 실제로 설치된 패키지만 참조한다.** 미설치 어셈블리를 참조하면 Unity가 매 컴파일마다 오류를 내기 때문이다.

현재 참조 중:
`Unity.TextMeshPro`, `UnityEngine.UI`, `Unity.InputSystem`, `Unity.AI.Navigation`,
`Unity.RenderPipelines.Core.Runtime`, `Unity.RenderPipelines.Universal.Runtime` (Gameplay/UI/Composition만)

### 5.1 도입 검토가 필요한 패키지

SCPPJ는 아래를 쓰고 있으나 SRPG에는 아직 없다. **패키지 설치는 프로젝트 전반에 영향을 주므로 별도 결정 사항으로 남겨둔다.**

| 패키지 | 매니페스트 항목 | 용도 | 우선도 |
|---|---|---|---|
| VContainer | `"jp.hadashikick.vcontainer": "https://github.com/hadashiA/VContainer.git?path=VContainer/Assets/VContainer#1.19.0"` | DI. `Core/DI`·`Composition`이 이걸 전제로 설계됨 | **높음** |
| Mathematics | `"com.unity.mathematics"` | 벡터·곡선 연산, Job 호환 | **높음** |
| Collections | `"com.unity.collections"` | 영향력 맵·플로우 필드 네이티브 배열 | 중간 |
| Burst | `"com.unity.burst"` | AI/패스파인딩 성능 | 중간 |
| Addressables | `"com.unity.addressables": "2.9.1"` | 에셋 로딩 | 중간 |
| Unity Behavior | `"com.unity.behavior": "1.0.16"` | BT 그래프 저작 (`08.Behavior/`) | 낮음 |
| Splines | `"com.unity.splines": "2.9.0"` | 경로·연출 | 낮음 |

도입 시 각 asmdef의 `references` 배열에 해당 어셈블리명을 추가해야 한다.

## 6. 코딩 규약

루트에 `.editorconfig`를 SCPPJ에서 그대로 가져왔다. 요점:

- 기본 인코딩 **UTF-8**, 줄바꿈 **CRLF**, 들여쓰기 **스페이스 4칸**
- `.cs` / 셰이더 → **UTF-8 with BOM**
  이유: Unity·Visual Studio가 BOM 없이는 한글 주석을 CP949로 오인해 저장하는 사고가 있다.
- `.json` / `.csv` / `.md` 등 데이터 파일 → **BOM 없는 UTF-8**, 들여쓰기 2칸
  이유: CSV 임포터 같은 커스텀 파서가 BOM을 첫 컬럼 값으로 읽는 사고 방지.
- Unity 직렬화 YAML(`.unity`, `.prefab`, `.asset`, `.meta` 등) → Unity가 쓰는 형식 그대로 둔다.

`.gitignore` / `.gitattributes`도 함께 복사했다. **단, SRPG는 아직 git 저장소가 아니다.** 버전 관리를 시작하려면 `git init`이 필요하다.

## 7. 빈 폴더 유지

git은 빈 디렉터리를 추적하지 않으므로 모든 빈 폴더에 `.gitkeep`을 넣어두었다. 해당 폴더에 실제 파일이 생기면 `.gitkeep`은 지워도 된다.
